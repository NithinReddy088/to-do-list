# Self-hosted OTA — operating guide

## One-time setup
1. Generate signing keys on the server: `cd apps/server && bun run codesign:generate`.
2. Copy the **public** key into the app's env so builds embed it:
   - `cat apps/server/keys/public-key.pem`
   - Paste into `apps/mobile/.env.<env>` as `CODE_SIGNING_CERTIFICATE` (full PEM).
3. Point `UPDATES_URL` in `apps/mobile/.env.<env>` at your server's
   `/api/manifest` (e.g. `https://todo.example.com/api/manifest`).
4. Keep `runtimeVersion` ("1.0.0") identical in `app.config.ts` and on published
   updates. Bump it only when native code changes.

## Publishing an update
From `apps/mobile`, with the server running and reachable:
```bash
PLATFORM=ios \
RUNTIME_VERSION=1.0.0 \
SERVER_BASE_URL=https://todo.example.com \
ADMIN_PUBLISH_TOKEN=<your token> \
SERVER_STORAGE_DIR=/abs/path/to/apps/server/updates \
bun run publish:update
```
The app pulls the new bundle on next launch (or via Settings → Check for updates).

## What OTA can and cannot do
- ✅ Ship JS/TS, styles, assets, and most React changes.
- ❌ Ship new native modules / native config — those need a new build and a
  `runtimeVersion` bump.

## Code signing — current state and the hardening step (IMPORTANT)

Our server signs every manifest with a **raw RSA keypair** generated by
`cd apps/server && bun run codesign:generate` (`keys/private-key.pem` +
`keys/public-key.pem`). The manifest signature is emitted in the multipart
response as the `expo-signature` header and has been **verified cryptographically
end-to-end** (the server's unit tests verify the signature against the public key,
and the OTA E2E confirms a real signature is served on `/api/manifest`).

However, this raw RSA keypair is **not yet wired into Expo's CLIENT-SIDE
signature verification**. Enabling `updates.codeSigningCertificate` in
`app.config.ts` requires the certificate to be in **Expo's expected X.509
certificate format** — a raw SPKI/PKCS8 PEM pair is not sufficient. The simplest
supported path is:

1. Generate an Expo-format cert + key:
   ```bash
   cd apps/mobile && npx expo-updates codesigning:generate \
     --key-output-directory keys \
     --certificate-output-directory certs \
     --certificate-validity-duration-years 10 \
     --certificate-common-name "Todo OTA"
   ```
2. Configure the app with the generated **certificate** (set
   `CODE_SIGNING_CERTIFICATE` in `apps/mobile/.env.<env>` to the full PEM of
   `certs/certificate.pem`). `app.config.ts` already reads that env var and, when
   set, adds:
   ```ts
   codeSigningCertificate: process.env.CODE_SIGNING_CERTIFICATE,
   codeSigningMetadata: { keyid: "main", alg: "rsa-v1_5-sha256" },
   ```
3. Have the **server sign manifests with the matching private key** (point
   `CODE_SIGNING_PRIVATE_KEY_PATH` at the Expo-generated `keys/private-key.pem`).

### Until that hardening step is done
- `CODE_SIGNING_CERTIFICATE` stays **empty** in `apps/mobile/.env.<env>`, so
  `app.config.ts` **omits** the `codeSigning*` keys entirely.
- OTA therefore runs **WITHOUT client-side signature verification**: the app still
  fetches and applies updates from our server, and the server still signs the
  manifest (the signature is just not validated on-device).
- This is acceptable for a trusted/self-hosted channel over HTTPS, but it does
  **not** protect against a compromised or spoofed update server. Completing the
  three steps above closes that gap and makes the on-device client reject any
  manifest not signed by our private key.
